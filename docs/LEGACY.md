# Pulse

Pulse — веб-приложение для сбора обратной связи студентов, анализа результатов и контроля улучшений. Для локального запуска нужен Node.js 24 или новее. Сервер и интерфейс используют встроенные возможности Node.js и браузера.

## Быстрый запуск на Windows

```powershell
$env:PULSE_DEMO = '1'
npm.cmd run legacy:start
```

Откройте [Pulse](http://127.0.0.1:3000) и выберите роль на экране входа. Демо включает шесть ролей, два учебных потока, шесть опросов и задачи на разных этапах. Пароль демонстрационных аккаунтов — `PulseDemo2026!`. Демо-данные сохраняются в `data/pulse-demo.sqlite`.

### Путь по демо

1. Войдите как **Edu Lead**. В **Surveys** создайте черновик, добавьте вопросы и опубликуйте опрос для **Python 12**.
2. Войдите как **Student**. Откройте приглашение в **Notifications**, сохраните черновик или отправьте ответы.
3. Войдите как **Edu Lead**. Откройте существующий **Python 12 · Mid-course survey** в **AI Insights**, запустите анализ, проверьте темы и опубликуйте результат. Из опубликованной темы можно создать задачу.
4. В **Issue Tracker** назначьте владельца и дедлайн, измените статус и привяжите повторный опрос. Сопоставимые результаты появятся после достижения порога ответов.
5. Войдите как **Director**. В **Reports** сравните данные, скачайте CSV или выберите **Print / PDF → Save as PDF**.

## Запуск с чистой базой

```powershell
$env:PULSE_DEMO = '0'
$env:PULSE_ADMIN_EMAIL = 'admin@academy.example'
$env:PULSE_ADMIN_PASSWORD = '<уникальный пароль от 12 символов>'
npm.cmd run legacy:start
```

Параметры первого администратора используются при создании новой базы. В **Administration** создайте курсы, группы и аккаунты. По умолчанию используется `data/pulse.sqlite`. `PULSE_DATABASE` задаёт отдельный файл базы, `HOST` и `PORT` задают адрес сервера. За HTTPS-прокси установите `PULSE_SECURE_COOKIE=1`. Разворачивайте один экземпляр сервера на файл базы.

### Анализ

Локальная классификация по правилам доступна без ключа и помечена в интерфейсе как **Local rules**. Для семантического анализа используйте совместимый с Chat Completions endpoint, поддерживающий JSON-ответ:

| Переменная | Значение |
| --- | --- |
| `PULSE_AI_URL` | Полный URL endpoint провайдера |
| `PULSE_AI_MODEL` | Имя модели у провайдера |
| `PULSE_AI_KEY` | Ключ из секретов окружения |
| `PULSE_ALLOW_EXTERNAL_AI` | Явное разрешение отправлять комментарии провайдеру. Значение `1` включает интеграцию |

При отправке используются временные номера комментариев и удаляются найденные email-адреса, ссылки и номера телефонов. Свободный текст может содержать другие персональные сведения. Перед включением внешнего анализа проверьте правила вашей организации и условия обработки провайдера. Приложение хранит результат в статусе **Review** до публикации сотрудником. Просроченные опросы с достаточной выборкой автоматически добавляются в очередь. Анализ можно запустить повторно.

### Docker и резервные копии

```powershell
docker build -t pulse .
docker run --rm -p 127.0.0.1:3000:3000 -e PULSE_DEMO=1 -v pulse-data:/app/data pulse
npm.cmd run backup -- data/pulse-demo.sqlite data/backup/pulse-demo.sqlite
```

Команда резервного копирования создаёт согласованную копию живой базы SQLite. Для восстановления остановите сервер и запустите его с `PULSE_DATABASE`, указывающим на новый файл, восстановленный из этой копии.

## Техническое устройство

| Модуль | Реализация |
| --- | --- |
| Интерфейс | Адаптивное одностраничное веб-приложение в `public/` |
| REST и RBAC | `src/api.js`. Сессии в базе, cookie HttpOnly/SameSite, пароли с scrypt |
| Схема и демонстрационные данные | `src/store.js`. SQLite с внешними ключами и WAL |
| Фоновые операции | `src/analysis.js`. Постоянная очередь анализа и транзакционная доставка уведомлений в приложение |
| Интеграционные проверки | `test/pulse.test.js`. HTTP-запросы к реальному серверу и временной базе |

`Course → Group → Student` задаёт аудиторию. Опрос связан с группой и преподавателем. Приглашение фиксирует участие, а ответ хранит значения вопросов. В анонимном режиме у ответов отсутствуют ID студента и время подачи, а черновик удаляется при отправке. Индивидуальные статусы приглашений скрыты от сотрудников. Доступ к статистике и запуску анализа зависят от минимальной выборки.

Результаты анализа версионируются, и задача ссылается на конкретную версию темы, исходный опрос и при необходимости повторный опрос. Историческая аналитика сверяет группы, типы опросов и формулировки рейтинговых вопросов. Сравнения преподавателей и групп дополнительно показывают число приглашений и ответов.

| REST | Назначение |
| --- | --- |
| `/api/login`, `/api/logout`, `/api/me` | Вход, выход и профиль |
| `/api/surveys`, `/api/surveys/:id` | Список, черновики, статистика и действия `publish`, `draft`, `answer`, `analysis` |
| `/api/analyses/:id` | Проверка и публикация результата |
| `/api/notifications` | Приглашения и напоминания |
| `/api/dashboard` | Метрики, тренды, группы и преподаватели |
| `/api/issues`, `/api/issues/:id` | Задачи, история и follow-up |
| `/api/admin` | Пользователи, курсы, группы и порог критического снижения |
